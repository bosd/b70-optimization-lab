# A320 prereg: what the 16-wide W13 tile should be worth on MTP0

Written while A320 loads, so the prediction cannot be fitted to the result.

**The change.** One line of the tuned map: `W1_CONFIG.BLOCK_SIZE_N` 32 → 16, on the
fused-QSA MTP0 record packet (A304) with the allowlist widened to admit the tile. Nothing
else moves.

**Why MTP0.** A phase delta resolves only at M=1. MTP0 captures
`cudagraph_capture_sizes: [1]`; MTP1 verifies two positions, runs M=2, drops the delta, and
prefers 64 anyway. A317/A318 established that the hard way.

**Predicted size.** The isolated probe puts W13 at 69.08 µs per layer at 16 against 77.30 at
32, so −8.18 µs per layer and −0.39 ms across 48 layers. A304 ran at 33.32–33.45 tok/s,
about 29.9 ms per step, so the tile is worth roughly **1.3%, or +0.44 tok/s**, landing near
**33.9**.

That is the number to beat, and it is small. A304's own two exact-2K rows differ by 0.125
tok/s, so a real effect should clear its own noise about threefold — but a result of, say,
+0.15 is not a win, it is spread, and I will report it as such. A result well above +0.44
is also suspect and would mean something other than the tile moved.

**Predicted exactness.** No change. The N tile decides which output columns a program owns
and leaves every element's K loop identical; 300 offline decode cases showed zero differing
elements of 3,840,000, and A317/A318 both returned their lineage hashes on the server. A320
must return `afffd2110812…` at exact-2K and `1d833e5f4633…` at exact-4K. If either moves,
the tile is not exact and the offline screen missed it — which would be the more interesting
result, and would disqualify the tile as a lossless lever regardless of speed.

**What would make this publishable.** A320 runs the full frozen client, so a win needs its
gates green (`PASS recovery quality short-repeat exact-2K-repeat exact-4K-repeat`), the
hashes unmoved, and then the standard deterministic repeat and fresh-server pair before the
MTP0 record is republished.

**Isolated-harness caveat.** Isolated probes have mispredicted this server twice (A282,
A286) and a third time in effect at A317, where the knob was not even connected. This
prediction is a filter, not a forecast.
